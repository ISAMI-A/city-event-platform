# 踩坑日志（城建平台）

> 每次踩坑后记录，开发前先回看避免复发。格式：日期 / 现象 / 根因 / 解决。
> 项目结构：6 个 Spring Boot 微服务 + Nacos + Gateway + MySQL/Redis/RabbitMQ/Seata + 管理后台 + 微信小程序。

## 2026-10-21 · 基础设施与工程骨架（P1）

### 坑 1：本机 MySQL 占用 3306，容器必须换端口
- 现象：`docker compose up` 后 MySQL 容器起不来，提示 3306 被占用。
- 根因：本机已安装 MySQL 8.4 并监听 3306。
- 解决：容器映射改为 `3307:3306`（`MYSQL_HOST_PORT=3307`），**同时** `MYSQL_PORT=3307` 供 Java 服务连接；两者必须一致，否则 Druid 初始化连 3306 连到本机库。

### 坑 2：初始化 SQL 中文变乱码
- 现象：种子数据里的中文（事件标题、区域名）入库后显示 `??` 或乱码。
- 根因：`docker-entrypoint-initdb.d` 执行时客户端字符集不是 utf8mb4，按 latin1 解析 UTF-8 文件。
- 解决：所有初始化 SQL 开头加 `SET NAMES utf8mb4;`；已入库的乱码用 `10-fix-seed-encoding.sql` 重新 UPDATE。新增 SQL 一律遵守。

### 坑 3：Nacos 发布配置返回 404
- 现象：用 PowerShell `Invoke-RestMethod` 发布 `city-common.yaml` 一直 404。
- 根因：表单编码与 URL 拼接在 PowerShell 下被处理坏，且脚本变量拼接后的 URL 与服务端期待不一致。
- 解决：改用 `curl.exe --data-urlencode`，URL 使用字面量而不是变量拼接；发布后到控制台核对内容。

### 坑 4：`lb://` 路由 503，event-service 找不到 user-service
- 现象：网关转发报 503，日志提示无可用实例。
- 根因：`event-service` 少了 `spring-cloud-starter-loadbalancer`，`@FeignClient` 无法解析服务名。
- 解决：在依赖 `common-api` 的模块中补充 `spring-cloud-starter-loadbalancer`；新增服务时检查该项。

### 坑 5：Sa-Token 上下文在网关与下游都拿不到
- 现象：网关偶发 500；下游 `LoginUser` 为 null。
- 根因：1) 自写 `AuthHeaderGlobalFilter` 在 WebFlux 异步链路里操作 Sa-Token ThreadLocal，上下文已丢失；2) 下游 `UserContextFilter` 的 Order 早于 Sa-Token 过滤器，上下文未初始化。
- 解决：网关**只做 token 校验**，不再读写 ThreadLocal；下游通过共享 Redis 会话在 `SaInterceptor` 内解析用户；全局异常处理器加 `@Order(HIGHEST_PRECEDENCE)`，避免被通用异常处理器抢匹配。

### 坑 6：`HandlerMethodValidationException` 方法不存在
- 现象：全局异常处理编译/运行报 `getParameterValidationResults()` 不存在。
- 根因：Spring Boot 3.2 的该异常 API 与旧版本不同。
- 解决：改用 `getAllValidationResults()` + `getResolvableErrors()`。

### 坑 7：`t_worker_profile` 缺审计字段导致插入失败
- 现象：创建处理人档案报 SQL 错误，提示 `create_by` 无默认值。
- 根因：实体继承审计基类，但初始化 SQL 漏了 `create_by/update_by`。
- 解决：`ALTER TABLE` 补列并同步修改 `01` 初始化脚本；新增表时对照实体字段逐个核对。

## 2026-10-21 · 业务闭环与分布式事务（P3 / Seata）

### 坑 8：Seata 镜像名错误
- 现象：`seataio/seata-server:2.1.0` 拉取失败。
- 解决：使用 `apache/seata-server:2.1.0`。

### 坑 9：Seata Server 启动缺配置占位符
- 现象：容器反复重启，日志提示缺少 `logging.file.path`、`console.user`、`seata.security.secretKey`。
- 根因：自定义 `application.yml` 覆盖了镜像默认配置，但没补全所有必填项。
- 解决：以镜像内默认 `application.yml` 为基线重写 `deploy/seata/application.yml`，只改动存储/注册部分。

### 坑 10：Seata 客户端连容器内网 IP 超时
- 现象：业务服务启动后 Seata 报连接超时，注册到 Nacos 的地址是 Docker 内网 IP。
- 根因：宿主机进程无法路由到容器内网地址。
- 解决：客户端改 `seata.registry.type=file`，`grouplist.default=127.0.0.1:8091` 直连映射端口；生产环境应改为可路由地址或 db 存储。

### 坑 11：8091/8092 端口冲突
- 现象：Seata 容器占用 8091，静态服务器启动失败。
- 解决：管理后台静态服务改用 8092，最终由 Nginx 容器托管。

### 坑 12：管理后台跨域与浏览器私有网络拦截
- 现象：页面请求接口 `ERR_FAILED`，控制台提示 Private Network Access / CORS。
- 根因：浏览器对 `公网页面 → 127.0.0.1` 的私有网络请求有拦截策略，加上旧的 index 缓存。
- 解决：管理后台改由 Nginx 同源反代 `/api/` 与 `/uploads/`，前端 `BASE=""`；Nginx 加 `Cache-Control: no-store`，避免改动后仍加载旧页面。

## 2026-10-21 · AI、地图与前端联调（P4）

### 坑 13：工单结果附件仍是 TEMP 状态
- 现象：处理人提交结果后，附件在详情里查不到。
- 根因：只上传了文件，没有把附件绑定到工单业务。
- 解决：新增 `EventClient.bindAttachments` 与 `AttachmentService.bindForWorkOrder`，提交结果时绑定并校验状态为 `BOUND`。

### 坑 14：熔断规则始终不触发
- 现象：故意让 AI 变慢，熔断一直不生效。
- 根因：`DegradeRule` 的 `minRequestAmount=2` + 10 秒统计窗口，4 次慢调用分散在窗口外，不满足比例条件。
- 解决：演示规则改为 `minRequestAmount=1`、`slowRatioThreshold=1.0`、`statIntervalMs=10000`，并用脚本顺序压测验证 `CIRCUIT_OPEN` 与恢复。

### 坑 15：腾讯地图 Key 的三种 Key 不是一回事
- 现象：只有 WebServiceAPI Key，浏览器加载 JSAPI 失败；控制台给的 SK 也不能当地图 Key 用。
- 根因：腾讯位置服务把 WebServiceAPI Key、Web 端 JSAPI Key、签名密钥 SK、小程序 APP ID 授权分开管理。
- 解决：服务端逆地址解析用 `TENCENT_MAP_KEY`；管理后台底图用同 Key 配置为 `TENCENT_MAP_JS_KEY`（需勾选 Javascript API GL）；SK 只在启用“签名校验”时使用，绝不能放前端。当前配额错误 `status=121` 属每日调用量上限，不是鉴权失败。

## 2026-10-21 · Redis / MQ / Sentinel / Seata 完善（P5）

### 坑 16：缓存命中绕过权限校验
- 现象：缓存事件详情后，其他居民也能看到该事件。
- 根因：最初直接把缓存对象返回，跳过了归属校验。
- 解决：缓存对象里保留 `reporterId`，命中缓存后仍执行 `assertCanView`；不存在的事件写 60 秒空值缓存防穿透。

### 坑 17：消息发送成功不等于业务成功
- 现象：派单通知偶发与工单状态不一致。
- 根因：早期把“消息已发送”当成“工单已创建”。
- 解决：生产端在本地事务 `afterCommit` 发送；消费端先经 Feign 复核工单状态与处理人，再写通知；Redis 幂等键 + 数据库唯一索引 `uk_notify_user_biz` 双保险；失败 `nack(requeue=false)` 进死信队列并记 ERROR。

### 坑 18：Seata 故障注入验证被误当成“接口报错即回滚”
- 现象：故障注入后接口 50301，但需要确认事件状态与两库 `undo_log`。
- 解决：验收必须同时查 `t_event.status`、`t_work_order` 记录、两库 `undo_log` 计数；关闭故障后再验证正常提交。禁止用手工改库伪造回滚。

## 2026-10-22 · 小程序、腾讯底图与启动器

### 坑 19：小程序详情页照片加载失败
- 现象：真机/模拟器详情页照片空白，控制台报 `Failed to load image http://127.0.0.1:19805/__pageframe__/uploads/...`。
- 根因：后端返回的是相对路径 `/uploads/...`，小程序 `<image>` 把它当本地资源解析；且网关当时没有 `/uploads/**` 路由。
- 解决：前端用 `baseUrl + accessUrl` 拼绝对地址；网关新增 `/uploads/** → event-service` 路由。修改网关配置后必须重新打包并重启（配置在 jar 内）。

### 坑 20：Windows PowerShell 5.1 运行脚本报“缺少 Catch/Finally”
- 现象：`.\start.ps1` 报语法错误，提示行号处的 `}`、字符串缺少终止符。
- 根因：脚本是无 BOM 的 UTF-8，PowerShell 5.1 按 GBK 解析，中文字符把引号配对破坏。
- 解决：脚本保存为 **UTF-8 with BOM**；改完用 `powershell.exe` 的 `Parser::ParseFile` 复验。新建含中文的 `.ps1` 一律带 BOM。

### 坑 21：微信开发者工具 CLI 提示服务端口关闭
- 现象：`cli.bat open --project ...` 报 `IDE service port disabled`。
- 解决：工具 → 设置 → 安全设置 → 打开“服务端口”（本次为 15002）；再执行 CLI。项目根目录需有 `project.config.json`（`miniprogramRoot=miniprogram/`），不要在 `miniprogram/` 下重复放一份。

### 坑 22：Vue 3 中 TMap 实例被响应式代理，图层静默失效
- 现象：腾讯地图底图正常，但事件点位圆点怎么都不显示，控制台无任何报错；同样代码在独立 HTML 里正常。
- 根因：TMap 实例放进 Vue `data` 后被 reactive 深度代理，内部渲染逻辑失效且不抛异常。
- 解决：实例赋值时用 `markRaw(...)`（Map/MultiCircle/InfoWindow 都要）。同类第三方实例（地图、图表、编辑器）都按此处理。

### 坑 23：服务进程随启动命令的终端退出而被清理
- 现象：手动用 `Start-Process java -jar` 拉起 5 个服务，终端命令结束后端口全部消失，只剩单独启动的那个。
- 根因：子进程挂在当前 Shell 的作业对象下，Shell 退出时被一并终止。
- 解决：统一用 `start.ps1` 常驻运行，由脚本管理全部子进程；或使用真正脱离会话的方式启动。

### 坑 24：不加载 `.env` 直接启动服务 → Druid 连错库
- 现象：`java -jar` 启动 event-service 报 `Connection refused`，日志里连的是 3306。
- 根因：未加载 `deploy/.env`，`MYSQL_PORT` 用默认 3306，而容器映射是 3307。
- 解决：所有启动方式先加载 `deploy/.env`；`start.ps1` 已内置，手动启动时也要先导入。

### 坑 25：打包时 jar 被运行进程锁定
- 现象：`mvn package` 报 `Unable to rename gateway-service-1.0.0-SNAPSHOT.jar to .original`。
- 根因：网关进程仍在运行，Windows 文件锁未释放。
- 解决：打包前先结束占用 8080–8085 的 java 进程；`start.ps1` 在需要打包时会自动 `Stop-PortOwner`。

### 坑 26：无头浏览器/非安全上下文获取不到定位
- 现象：管理后台点击“定位我”，10 秒后提示“定位超时，请重试”，没有权限弹窗，也没有蓝色定位标记。
- 根因：自动化浏览器没有系统定位源；`navigator.geolocation` 只在 localhost 或 HTTPS 安全上下文可用，且需要用户明确授权。
- 解决：已在代码中区分权限拒绝(1)/定位不可用(2)/超时(3)三种提示；成功路径必须在 localhost 或 HTTPS 的真实浏览器中允许定位后验证，不要把自动化无头环境作为定位成功与否的依据。

### 坑 27：定位点用 MultiCircle 会随缩放变大变小
- 现象：定位点半径按“米”设置时，地图放大后圈很大、缩小时几乎看不见，还和状态图例混在一起。
- 根因：`TMap.MultiCircle` 的 `radius` 单位是米，像素大小随缩放变化；定位精度 `accuracy` 本身可能上万米。
- 解决：定位点改用 `TMap.MultiMarker` + 26px SVG 图标（`MarkerStyle` 的 width/height 为像素），缩放时大小不变；需要精度范围再加独立半透明圆，且限制最大半径。另：JSAPI GL 只内置缩放/比例尺/3D 罗盘控件，没有定位控件，定位按钮以地图内嵌图标按钮实现。

### 坑 28：GLM-4.6V-Flash 免费模型高峰期限流
- 现象：视觉核实调用返回 `429 {"code":"1305","message":"该模型当前访问量过大"}`；付费的 `glm-4.6v` / `glm-4.6v-flashx` 返回 `1113 余额不足`。
- 根因：免费视觉模型有平台级并发/时段限制，与 Key 是否正确无关。
- 解决：文本分析继续用 `glm-4-flash`，视觉核实用 `LLM_VISION_MODEL=glm-4.6v-flash`，并配置 `LLM_VISION_FALLBACK_MODEL=glm-4v-flash` 自动回退；结果中的 `model` 字段记录实际使用模型，文档不得把回退写成主模型成功。

### 坑 29：PowerShell `-Form` 上传图片被判定“文件类型不支持”
- 现象：`Invoke-RestMethod -Form @{ file = Get-Item x.jpg }` 上传返回 `文件类型不支持`。
- 根因：PowerShell 默认把文件 part 的 Content-Type 设为 `application/octet-stream`，后端只接受 `image/jpeg` / `image/png`。
- 解决：改用 `HttpClient + MultipartFormDataContent`，显式设置 `Content-Type: image/jpeg`；或使用 curl 的 `-F "file=@x.jpg;type=image/jpeg"`。

### 坑 30：上传目录从 `uploads/` 切到 `data/uploads` 要迁移旧文件
- 现象：改 `UPLOAD_ROOT` 后，数据库里已有的 `/uploads/2026/10/22/xxx.jpg` 访问 404。
- 根因：数据库存的是相对访问路径，静态映射根目录变了，旧文件不会自动跟过去。
- 解决：迁移前把旧目录文件按相同的 `年/月/日/文件名` 复制到新目录，再重启 event-service；`uploads/`、`data/` 都已在 `.gitignore` 中排除。

### 坑 31：SBA 同时用 client 注册和 Nacos 发现会出现重复实例
- 现象：SBA 面板显示 12 个实例，每个服务出现两次（一次 `127.0.0.1`，一次局域网 IP）。
- 根因：`spring-boot-admin-starter-client` 主动注册 + SBA Server 检测到 `DiscoveryClient` 后自动从 Nacos 纳管，同一服务被登记两次。
- 解决：只保留一种模式。当前使用 Nacos 发现（`monitor-service` 依赖 `spring-cloud-starter-alibaba-nacos-discovery`，各服务只需 actuator），移除各服务的 SBA client 依赖与 `spring.boot.admin.client` 配置；重启后为 7 个实例、无重复。

### 坑 32：内嵌在地图上的自定义按钮点了没反应
- 现象：管理后台地图右下角的定位按钮显示正常、鼠标也变成手型，但点击毫无反应，控制台无报错。
- 根因：TMap JSAPI GL 会在地图容器内注入一个覆盖整个地图的透明交互层 DIV（`position:absolute; inset:0; z-index:1000; pointer-events:auto`），自定义按钮 `z-index` 低于它时点击被整层吞掉；该 DIV 在 DOM 里看不到任何内容，容易误判为地图控件或版权元素遮挡。
- 解决：地图内自绘按钮的 `z-index` 必须大于 1000（本次设 1200）。排查时用 `document.elementFromPoint(按钮中心x, 按钮中心y)` 看返回的是不是按钮本身；若返回一个空 className、`z-index:1000`、覆盖全图的 DIV，就是腾讯地图交互层。

### 坑 33：地图缩小后事件圆点看不见、密集区域重叠
- 现象：事件点用 `MultiCircle` + 固定 `radius`（米）渲染，缩小时点几乎消失，同区域多点叠在一起分不清，也没有数量提示。
- 根因：圆的半径单位是米，像素大小随缩放变化；且没有聚合逻辑。
- 解决：改用 `MultiMarker` + SVG data URI 图标（`MarkerStyle` 宽高为像素），按缩放级别分档设定图标尺寸；监听地图 `idle` 事件，按当前缩放级别的世界像素网格（64px）聚合，聚合图标上写事件数量，颜色取该网格内数量最多的状态；点击聚合图标用 `InfoWindow` 列出事件单号/状态/优先级，单点显示单号与地址。点位与聚合模型不要放进 Vue 响应式数据。

### 坑 34：小程序改为自定义 tabBar 后跳转失效
- 现象：把「我的事件/我的工单/我的」设为 tabBar 页面后，原 `wx.navigateTo({url:"/pages/events/events"})` 直接失败或白屏。
- 根因：tabBar 页面只能通过 `wx.switchTab` / `wx.reLaunch` 打开，`navigateTo` 不允许跳到 tab 页；自定义 tabBar 组件还必须声明 `{"component": true}`，且每个 tab 页要在 `onShow` 里调用 `this.getTabBar().sync(...)` 同步选中态。
- 解决：所有指向 tab 页的跳转改用 `wx.switchTab`；上报页提交成功后也用 `switchTab` 回列表；页面底部预留 `calc(140rpx + env(safe-area-inset-bottom))`。

### 坑 35：改完前端页面仍显示旧版布局
- 现象：管理后台已重写为左侧导航，但浏览器/自动化工具打开后仍是旧的顶部 3 个 tab，接口和数据都是新的。
- 根因：已打开的标签页沿用旧 JS，或浏览器复用了旧页面；Nginx 的 `Cache-Control: no-store` 只影响新请求，不会让已加载的实例自动刷新。
- 解决：开发期用带版本参数的地址强制加载（如 `/?v=20261022b`），或 Ctrl+F5；排查时先判断 `document.body.innerText` / 是否存在 `aside.sidebar`，确认拿到的是新版再继续验证，别把旧页面现象当成新代码 bug。

### 坑 36：PowerShell 联调脚本把业务失败当成成功
- 现象：调用“禁止修改自己账号状态”“无工人档案不能加 WORKER 角色”等接口时，脚本没有抛异常，反而打印“成功”。
- 根因：项目统一异常处理返回 HTTP 200 + `{code:40301,...}`，`Invoke-RestMethod` 只按 HTTP 状态码判断，不会因 `code != 0` 抛错。
- 解决：联调脚本必须显式检查 `body.code -eq 0`；需要看真实错误时用 `Invoke-WebRequest.Content` 或读取响应 JSON 的 `code/message`，不能只看是否抛异常。

### 坑 37：in-DOM 模板里自闭合自定义组件导致表头 colspan、表格空列
- 现象：管理后台事件表/工单表出现多级表头（`th` 带 `colspan`）、列体全空、后面列被挤没；表单里输入框与按钮错位、图片网格布局异常。
- 根因：`index.html` 的模板直接写在 `<div id="app">` 里，由浏览器先按 HTML 规则解析，再交给 Vue 编译。HTML 解析器不认自闭合的自定义标签，`<el-table-column ... />` 会当作“未闭合的开始标签”，把后续兄弟节点全部嵌进去；`el-table` 便把这些嵌套列当成**多级表头分组**，于是出现 `colspan` 和空列。同理 `<el-option />` 会吞掉 `</el-select>` 之后的兄弟节点，`<el-input />`、`<el-image />`、`<el-pagination />` 造成表单与网格错位。
- 解决：in-DOM 模板中所有自定义组件（`el-*`）一律写成成对标签，禁止 `<xxx />` 写法：`<el-table-column ...></el-table-column>`、`<el-option ...></el-option>`、`<el-input ...></el-input>`、`<el-image ...></el-image>`、`<el-pagination ...></el-pagination>`。用单文件 `.vue` 或字符串模板编译时自闭合没问题，但本项目是全局构建 + in-DOM，必须遵守。
- 排查：`/>$` 搜索模板区，凡是 `el-` 开头的自闭合标签都要改；改完在浏览器 DevTools 里确认表头 `th` 没有 `colspan`。

### 坑 38：AI 核实总是 `NO_IMAGE`，但请求里明明带了照片
- 现象：管理端点“AI 核实”一直显示“无法判断｜置信度 0（降级：NO_IMAGE）”，`t_ai_call_log.request_summary` 里却是 `images=1`。
- 根因：`RectifyVerifyService` 早期限制“单张超过 2MB 直接跳过”，微信 `chooseMedia` 的 compressed 原图仍有 2.7MB，被静默跳过，最终可用图片数为 0，于是按无图降级；从接口层看请求确实带了 1 张图片，容易误判成附件没绑定。
- 解决：不再按原图大小直接丢弃，改为读取后用 `ImageIO` 解码并等比压缩到最长边 1280px 的 JPEG（质量 0.82）再转 base64，读取上限放宽到 10MB；同时把“有图片引用但全部读取失败”降级为 `IMAGE_UNREADABLE`，与真正无图的 `NO_IMAGE` 区分开。
- 排查：先在 `ai-service` 日志搜“跳过”“整改照片”，能看到被跳过的附件 id 与字节数；再看 `images=` 统计是请求张数而不是可用张数。

### 坑 39：AI 核实只说“缺乏明确的整改目标”，因为根本没给事件原描述与原图
- 现象：整改核实结论长期是 `UNCERTAIN / 置信度 0`，依据写着“由于缺乏明确的整改目标和背景信息，无法确定是否有效”。
- 根因：核实请求只带了工单号、事件编号、类别、整改说明和整改后照片，没有居民上报的标题/地址/描述，也没有上报原图；模型不知道“原来要解决什么问题”，只能保守判无法判断。管理端工单弹窗同样只展示整改照片，管理员也没法前后对照。
- 解决：`workorder-service` 通过 `EventClient.snapshot` 与新增的 `/internal/v1/events/{eventId}/attachments` 取事件原描述与原图，一并放进 `RectifyVerifyRequest`；`ai-service` 把原图排在照片列表前面，提示词明确“前 N 张是整改前、后 M 张是整改后”，并以“原问题是否消失”为判定口径、整体从宽。工单详情 VO 增加 `eventPhotos`，管理端“关联事件”区块直接展示上报原图。
- 排查：看 `t_ai_call_log.request_summary` 是否同时有 `images=` 与 `originalImages=`；只带 `images=` 说明上下文没注入。

### 坑 40：小程序真机调试报 `SyntaxError: Unexpected token .`
- 现象：自动真机调试提示 `invalid file: pages/profile/profile.js`，指向 `this.data.me?.nickname`，报 `Unexpected token .`；对应页面白屏/逻辑中断。
- 根因：`project.config.json` 里 `setting.es6 = false`（不做 ES6→ES5 转译），而 TS 编译后的 JS 保留了可选链 `?.`（ES2020 语法），部分基础库/真机调试环境无法解析。
- 解决：小程序代码里禁用可选链 `?.` 与空值合并 `??`，改成显式判断：`const me = this.data.me; me ? me.nickname : ""`。提交前用 `grep "\?\.[a-zA-Z]" miniprogram` 扫一遍。

### 坑 41：真机 `<image>` 拒绝 HTTP 图片，缩略图空白但点开大图正常
- 现象：工单详情缩略图在真机上全部空白，`binderror` 报“图片链接 `http://10.123.159.42:8080/uploads/...` 不再支持 HTTP 协议，请升级到 HTTPS”；但 `wx.previewImage` 打大图正常。
- 根因：微信基础库对 `<image>` 组件强制要求 HTTPS，这是组件级限制，与 `project.private.config.json` 的 `urlCheck: false`（只影响 request/downloadFile 域名校验）无关；开发环境后端只有 http，所以只有 `image` 组件失败，接口与 previewImage 不受影响。
- 解决：新增 `miniprogram/utils/image.ts` 的 `localImage()`，对 `http://` 地址先 `wx.downloadFile` 到本地临时文件再渲染（同地址做内存缓存，失败回退原地址）；所有展示远程图片的页面（工单详情、事件详情、驳回重提的原图、我的头像）统一走这个方法。
- 结论：上线前后端必须提供 HTTPS（Nginx + 证书），否则真机图片一律不显示。

### 坑 42：管理员派单下拉列出组员，组长复核链路被绕过
- 现象：审核弹窗的“处理人员”里出现组员，选中后工单直接派给组员，组长无法分配、也无法复核。
- 根因：`assignableWorkers` 只过滤了在岗状态，没有按 `workerType` 过滤；管理员与组长的派单对象语义不同。
- 解决：管理端审核下拉只保留 `workerType=LEADER` 的在岗组长；组员由组长在小程序端分配。演示数据重置后务必确认 4 名组长均为 `LEADER`、组员均设置了 `leader_id`。

### 坑 43：组长复核接口传布尔 `pass` 导致 400
- 现象：小程序组长复核一直失败，后端提示“复核结果不能为空”。
- 根因：`LeaderReviewRequest` 的字段是 `result`（PASS/REJECT），不是布尔 `pass`。
- 解决：小程序统一传 `{ result: pass ? "PASS" : "REJECT", remark }`；后端退回时强制要求填写复核意见。

### 坑 44：演示数据附件 `stored_name` 有唯一键，不能复用同一文件
- 现象：重置脚本执行到附件 INSERT 报 `Duplicate entry 'demo-wo09-result.jpg' for key 't_attachment.uk_attachment_stored'`。
- 根因：`t_attachment.stored_name` 是唯一键，两张工单整改照片不能指向同一个存储文件名。
- 解决：新增 `demo-wo13-result.jpg` 并同步到 `scripts/reset-demo.ps1` 的图片映射；每次新增附件行都使用独立 `stored_name`。

### 坑 45：组员访问组长接口返回 403 是预期行为
- 现象：组员登录小程序后打开“团队”或组内工单接口报错。
- 根因：`/api/v1/workorders/team`、`/team/stats`、`/api/v1/workers/my-team` 都要求 `workerType=LEADER`，普通组员无权访问。
- 解决：小程序先调用 `/api/v1/workers/me/profile` 判断 `workerType`，只有组长展示“团队/分配/复核”入口；组员按“我的工单”加载，接口异常时降级而不是白屏。

### 坑 46：工单详情全部“系统繁忙”，根因是评分表缺审计字段
- 现象：管理端工单管理点“查看/处理”，所有工单都返回“系统繁忙，请稍后重试”；列表接口正常，仅详情失败。
- 根因：`WorkRating` 实体继承 `BaseEntity`，MyBatis-Plus 查询会自动带上 `update_time/create_by/update_by/deleted/version`，但 `13-team-recruitment.sql` 建 `t_work_rating` 时只写了 `create_time`；工单详情会顺带查询居民评分，于是每条详情都报 `Unknown column 'update_time' in 'field list'`。
- 解决：给 `t_work_rating` 补齐 `update_time/create_by/update_by/deleted/version`，并同步修改 `13-team-recruitment.sql`。新建表时一律对照 `BaseEntity` 逐个补齐审计字段，即使当前业务不需要。
- 排查：服务日志搜 `Unknown column`，再看实体是否继承 `BaseEntity` 而建表 SQL 漏列。

## 2026-10-23 · 账号体系补全与邮箱验证

### 坑 47：微信快捷登录后个人页没有登录账号
- 现象：微信首次登录自动建的居民账号，个人页“登录账号”一直显示 `-`，用户也不知道自己账号是什么。
- 根因：`wxRegister` 只写了 `open_id/nickname/status`，没有生成 `username`；`t_user.username` 虽可空，但页面按账号展示时会空白。
- 解决：注册时自动生成 `wx_` + 6 位随机字符（去掉易混淆的 `0/o/1/l/i`），冲突最多重试 10 次；存量数据用 `14-user-email.sql` 按 id 补齐为 `wx_000123`。登录账号只读展示，密码/手机号/邮箱由用户自助补充。

### 坑 48：MyBatis-Plus `updateById` 无法把邮箱置空
- 现象：解绑邮箱后数据库 `email` 仍是原值。
- 根因：MyBatis-Plus 默认 `FieldStrategy.NOT_NULL`，`updateById` 会忽略值为 null 的字段。
- 解决：解绑用自定义 SQL `clearEmail` 显式 `SET email = NULL, email_verified = 0`；微信解绑同理走 `clearWechatBinding`。

### 坑 49：SMTP 未配置时验证码“发送成功”但收不到邮件
- 现象：本地点“发送验证码”提示成功，邮箱里没有邮件。
- 根因：`MAIL_USER` 为空时按 `MAIL_LOG_CODE=true` 走日志兜底，并没有真正发信。
- 解决：`deploy/.env` 填 `MAIL_USER`（完整 QQ 邮箱）+ `MAIL_PASS`（QQ 邮箱“设置-账户”生成的 SMTP 授权码，不是登录密码），并把 `MAIL_LOG_CODE` 改为 `false`；联调时到 user-service 日志搜 `[mail]` 取验证码。

### 坑 50：编辑页 `onShow` 重新加载会冲掉正在输入的邮箱/验证码
- 现象：用户在编辑页填新邮箱后切到邮箱 App 复制验证码，返回小程序时输入框被清空。
- 根因：页面 `onShow` 会重新拉取 `/auth/me` 并覆盖 `emailInput` 等输入项。
- 解决：`load()` 只刷新只读状态，不回写正在编辑的输入；头像仅在存在草稿时才保留本地预览。输入项只在切换展开面板或保存成功后清空。

### 坑 51：微信昵称输入框选了微信名，注册后仍显示 `居民__H9U`
- 现象：首次微信登录注册时选择了微信昵称，进入小程序后昵称仍是系统默认的 `居民_` + openid 后缀。
- 根因：`<input type="nickname">` 的昵称建议在失焦/合规回调时才真正写入，只监听 `bindinput` 时 `this.data.nickname` 仍为空，后端拿到空昵称走了兜底；兜底又直接截取 openid 末 4 位，遇到 `_H9U` 这类后缀出现双下划线。
- 解决：输入框补 `bindblur` 与 `bindnicknamereview` 回写昵称；后端兜底改为 `居民_` + 4 位随机字符（去掉易混淆字符），不再截取 openid。

## 常用检查清单（开发前 30 秒）

1. `deploy/.env` 是否存在且 `MYSQL_PORT` 与 `MYSQL_HOST_PORT` 一致（3307）。
2. 8080–8085 是否被旧 java 进程占用，jar 时间戳是否最新。
3. Docker 容器是否 healthy；6379 是否被非容器 Redis 占用（启动器会自动跳过容器 Redis）。
4. 改网关配置或依赖后是否重新打包并重启。
5. 新增含中文的 PowerShell 脚本是否带 BOM。
6. 第三方地图/图表实例是否用 `markRaw` 存入 Vue。
7. 改缓存逻辑后是否保留权限校验；改 MQ 消费后是否仍是“先复核业务状态再落库”。
8. 地图内自绘按钮/浮层 `z-index` 是否大于腾讯地图交互层（1000）。
9. 小程序 tabBar 页面之间的跳转是否统一用 `wx.switchTab`。
10. in-DOM 模板里是否残留自闭合的 `el-*` 组件（会破坏表格/表单布局）。
11. 视觉核实请求是否同时带上了事件原描述与上报原图（`originalImages`），否则结论会偏保守。
12. 小程序代码是否残留 `?.` / `??`（本项目关闭了 ES6 转译，真机会解析失败）。
13. 小程序展示远程图片是否走 `localImage()`（真机 `image` 组件不支持 http）。
14. 管理端审核派单下拉是否只列 `workerType=LEADER` 的组长（组员由组长分配）。
15. 新增工单状态/动作是否同步了管理端与小程序的状态文案、标签颜色与操作入口。
16. 事件上报/重新提交是否同时校验福州市六城区范围（后端 `FuzhouArea` + 小程序 `inFuzhou`）。
17. 新增附件行是否使用独立 `stored_name`（唯一键），演示图片映射是否同步到重置脚本。
18. 新建表是否对照 `BaseEntity` 补齐 `create_time/update_time/create_by/update_by/deleted/version`（漏列会导致查询该表的所有接口 500）。
19. 需要置空字段（解绑微信/邮箱）是否用自定义 SQL，而不是 `updateById`。
20. 新增可空唯一字段（如 `email`）是否允许 NULL，并在解绑时显式置空。
21. 邮箱验证码联调是否确认 `MAIL_USER/MAIL_PASS` 已配置，否则只会在日志里看到验证码。
