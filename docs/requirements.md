# 需求说明书

> 项目：基于大模型与地理位置服务的城市事件智能上报及工单调度平台
> 文档版本：v0.1（第一阶段规划稿）
> 状态：待评审，评审通过前不进入业务编码

---

## 1. 项目背景与目标

### 1.1 背景

城市管理中的道路破损、路灯故障、垃圾堆积、井盖缺失等问题，目前多依赖电话、微信群或线下反映，存在描述不规范、位置不精确、分类靠人工、派单无追踪等问题。本项目构建一套"居民上报 → AI 辅助分析 → 管理员审核 → 工单派发 → 现场处理 → 验收关闭"的闭环平台。

### 1.2 项目目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G1 | 业务闭环可演示 | 三种角色、完整状态流转，端到端跑通 |
| G2 | 技术栈真实生效 | Nacos / Gateway / Feign / Sentinel / Seata / MQ / Redis / 权限 / SBA 均有可复现验证 |
| G3 | 可部署 | 在 Linux 服务器通过 Docker Compose 一键启动 |
| G4 | 可答辩 | 文档、架构图、演示脚本、故障注入证据齐全 |

### 1.3 范围边界（明确不做）

- 不做真实支付、短信、实名认证、政务内网对接。
- 不做多租户、多城市隔离。
- 不做工单排班的智能算法优化（仅支持人工派单 + 手动改派）。
- 不做大模型微调，仅调用云端 API。
- 不做小程序审核上线（使用开发者工具 + 体验版演示）。

## 2. 角色与权限模型

系统采用 **RBAC（角色固定、用户可多角色）**，角色枚举固定为三种，不做动态菜单权限。

| 角色 | 编码 | 使用端 | 核心权限 |
| --- | --- | --- | --- |
| 居民 | `RESIDENT` | 微信小程序 | 注册/登录、上报事件、上传照片、地图选点、查看本人事件进度、确认 AI 分析结果、绑定/解绑微信 |
| 处理人员 | `WORKER` | 微信小程序（现场处理需拍照定位） | 登录、查看本人待办工单、接单、提交处理结果、AI 预检、查看历史工单、绑定/解绑微信 |
| 管理员 | `ADMIN` | Web 管理后台 | 审核事件、派单/改派、验收、用户与角色管理、统计与地图分布 |

补充约定：

- 一个用户可同时拥有多个角色，但同一时刻的登录态以所选角色为准（`activeRole`），避免越权。
- 处理人员额外归属一个"责任部门/工种"（如市政道路、路灯照明、环卫），用于派单筛选。
- 管理员账号由初始化 SQL 内置；居民可在小程序登录页用“用户名 + 密码 + 昵称 + 手机号”自助注册，处理人员账号仍由管理员创建。
- 已登录账号可在「我的」页绑定/解绑当前微信；解绑要求账号已有密码，避免解绑后无法登录。

## 3. 功能需求

### 3.1 居民端（小程序）

| 编号 | 需求 | 规则要点 |
| --- | --- | --- |
| FR-R01 | 微信登录 | `wx.login` 取 code → 后端 `code2session` 换 openid；已绑定直接登录；未绑定时引导选择身份：处理人员校验账号密码后绑定，居民确认后自动注册为 `RESIDENT`；token 由后端签发 |
| FR-R02 | 上报事件 | 必填：描述（10–500 字）、类别（可先由 AI 建议）、位置（经纬度 + 地址）、至少 1 张照片 |
| FR-R03 | 照片上传 | 最多 9 张，jpg/png，单张 ≤ 5MB；数据库只存元数据与访问路径，文件落磁盘/挂载卷 |
| FR-R04 | 地图选点 | 调用 `wx.chooseLocation` 获取 GCJ-02 经纬度与地址；后端调用地图服务补齐行政区、街道、区域编码 |
| FR-R05 | AI 分析 | 提交前调用 AI 分析，可同时携带已上传照片（最多 3 张），返回润色扩写后的事件描述、类别、摘要、优先级建议、建议处理措施、置信度；描述为空时由 AI 根据照片生成，展示给用户确认 |
| FR-R06 | 确认提交 | 用户可修改 AI 建议的类别后再提交；提交后状态为"待审核" |
| FR-R07 | 进度查看 | "我的事件"列表 + 详情，展示状态时间线、驳回原因、处理结果与照片 |
| FR-R08 | 撤销 | 仅"待审核"状态可撤销，撤销后不可恢复 |
| FR-R09 | 重新提交 | 被驳回的事件可修改描述/照片/位置后重新提交，保留原事件编号 |
| FR-R10 | 账号注册 | 登录页“注册居民账号”：用户名（字母开头 4-32 位）、密码（8-32 位）、昵称（2-20 字）、手机号（11 位、唯一）；注册成功自动登录 |
| FR-R11 | 微信绑定/解绑 | 「我的」页展示绑定状态：绑定走 `wx.login` 授权；解绑需二次确认且账号已有密码；绑定/解绑均不改变账号密码登录能力 |

### 3.2 处理人员端（小程序）

| 编号 | 需求 | 规则要点 |
| --- | --- | --- |
| FR-W01 | 账号登录 | 账号密码登录，角色校验为 `WORKER` |
| FR-W02 | 待办工单 | 按状态分组：待接单 / 处理中 / 待验收 / 已完成；只可见分配给自己的工单 |
| FR-W03 | 接单 | 仅"待接单"可接；并发接单需幂等（乐观锁/状态条件更新），重复接单返回状态冲突 |
| FR-W04 | 处理反馈 | 可多次添加处理记录（文字 + 照片），工单状态变为"处理中" |
| FR-W05 | 提交结果 | 必填处理说明 + 至少 1 张现场照片；提交后状态"待验收" |
| FR-W06 | 退回重做 | 验收不通过时，工单回到"处理中"，展示验收意见 |
| FR-W07 | 历史工单 | 按时间/状态查询本人历史工单 |

### 3.3 管理员端（Web）

| 编号 | 需求 | 规则要点 |
| --- | --- | --- |
| FR-A01 | 账号登录 | 账号密码登录（BCrypt），角色校验为 `ADMIN` |
| FR-A02 | 事件审核 | 查看待审核列表与详情；通过时确认/修正类别、优先级、区域；驳回时必填原因 |
| FR-A03 | 派单 | 审核通过时同步创建工单并指派处理人；支持按区域/工种筛选处理人 |
| FR-A04 | 改派 | 工单"待接单"或"处理中"可改派，需记录改派原因与操作人 |
| FR-A05 | 验收 | 查看处理结果与照片；通过则关闭事件，不通过则退回并填写意见 |
| FR-A06 | 用户管理 | 查询用户、启用/禁用、重置密码、分配角色、维护处理人员部门 |
| FR-A07 | 统计 | 事件总数、按状态/类别/区域分布、平均处理时长、近 7 日趋势 |
| FR-A08 | 地图分布 | 地图打点/聚合展示事件，支持按状态、类别、区域、时间筛选 |
| FR-A09 | 操作审计 | 审核、派单、验收等关键操作留痕（操作人、时间、前值/后值） |

### 3.4 事件类别字典

| 编码 | 名称 | 说明 |
| --- | --- | --- |
| `ROAD_FACILITY` | 道路设施 | 路面破损、井盖缺失、护栏损坏 |
| `PUBLIC_LIGHTING` | 公共照明 | 路灯不亮、线路裸露、灯杆倾斜 |
| `ENVIRONMENT_SANITATION` | 环境卫生 | 垃圾堆积、污水外溢、乱贴乱画 |
| `PUBLIC_FACILITY` | 公共设施 | 座椅、健身器材、公厕设施损坏 |
| `OTHER` | 其他 | 无法归类，必须人工确认 |

### 3.5 优先级

`LOW` / `MEDIUM` / `HIGH` / `URGENT`。AI 仅给"建议优先级 + 置信度"，最终值由管理员审核时确定；未审核时展示建议值并标注"AI 建议"。

## 4. 核心业务流程与状态机

### 4.1 主流程

```
居民提交
  └─> 待审核(PENDING_REVIEW)
        ├─ 管理员驳回 ──> 已驳回(REJECTED) ──居民修改重新提交──> 待审核
        ├─ 居民撤销 ──> 已撤销(CANCELLED)
        └─ 管理员通过（Seata 全局事务：改事件状态 + 建工单）
              └─> 已派单(DISPATCHED)
                    └─ 处理人员接单 ──> 处理中(PROCESSING)
                          └─ 提交结果 ──> 待验收(PENDING_ACCEPTANCE)
                                ├─ 验收不通过 ──> 处理中(PROCESSING)
                                └─ 验收通过 ──> 已关闭(CLOSED)
```

### 4.2 事件状态枚举

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| `PENDING_REVIEW` | 待审核 | 管理员通过/驳回；居民撤销 |
| `REJECTED` | 已驳回 | 居民修改重提 |
| `CANCELLED` | 已撤销 | 终态 |
| `DISPATCHED` | 已派单（待接单） | 处理人接单；管理员改派 |
| `PROCESSING` | 处理中 | 处理人提交结果；管理员改派 |
| `PENDING_ACCEPTANCE` | 待验收 | 管理员验收 |
| `CLOSED` | 已关闭 | 终态（可追加评价，非必需） |

### 4.3 工单状态枚举

| 状态 | 含义 |
| --- | --- |
| `PENDING_ACCEPT` | 待接单 |
| `PROCESSING` | 处理中 |
| `PENDING_ACCEPTANCE` | 待验收 |
| `RETURNED` | 验收退回（业务上等价处理中，单独记录次数） |
| `COMPLETED` | 已完成 |
| `REASSIGNED` | 已改派（历史记录，当前工单以新记录为准） |

> 状态变更统一由服务端校验合法迁移，非法迁移返回 `40901` 状态冲突；所有变更写入状态流水表。

## 5. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 性能 | 常规接口 P95 ≤ 500ms；AI 分析接口单独限时（≤ 15s，超时降级） |
| NFR-02 | 可用性 | 单服务异常不影响其他服务；AI/地图外部依赖故障时降级，不阻断上报主流程 |
| NFR-03 | 安全 | 密码 BCrypt；Token 存储于 Redis；越权访问返回 403；内部接口不对网关暴露；上传文件做类型与大小校验 |
| NFR-04 | 一致性 | 审核通过 + 建工单必须原子（Seata AT）；消息消费幂等 |
| NFR-05 | 可观测 | 全链路 `traceId`；Logback 结构化日志；SBA 展示健康状态；关键操作审计 |
| NFR-06 | 可维护 | 统一响应/错误码/校验/命名；模块边界清晰，禁止跨服务写库 |
| NFR-07 | 可部署 | Docker Compose 单机部署；配置通过 Nacos + 环境变量注入，镜像不含明文密钥 |

## 7. 假设与待确认事项

> 下列事项影响实现，需在编码前由项目负责人确认，未确认前按"推荐方案"标注执行，但不视为最终结论。

| 编号 | 事项 | 推荐方案 | 影响 |
| --- | --- | --- | --- |
| Q1 | 权限框架 | **Sa-Token 1.44.0**（轻量、网关集成官方模块、与 Redis 共享会话简单），不引入 Spring Security | 影响 common-security、网关过滤器、登录流程 |
| Q2 | 管理后台技术栈 | **Vue 3 + Vite + Element Plus + Pinia + Axios + ECharts**（团队熟悉 Vue） | 影响 admin-web 全部页面 |
| Q3 | 大模型供应商 | **DeepSeek（OpenAI 兼容）**，`ai-service` 做适配层，可切换供应商 | 影响 ai-service 适配器与提示词 |
| Q4 | 地图 Key 与配额 | 腾讯位置服务，需 3 类 Key | 影响小程序域名白名单、admin-web JSAPI |
| Q5 | Linux 部署环境 | Ubuntu 22.04 / 4C8G 起，Docker 24+ + Compose v2 | 影响镜像数量与内存分配 |
| Q6 | 处理人员使用端 | 小程序（现场拍照/定位更自然），不另做 Web 端 | 影响前端工作量 |
| Q7 | 文件存储 | 宿主机挂载卷 + Nginx 静态代理（不引入 MinIO） | 影响上传与访问路径 |
| Q8 | 是否演示微信真实登录 | 优先真实 `code2session`；无 AppSecret 时提供受控 mock 登录（仅 `dev` profile） | 影响演示稳定性 |

## 8. 术语表

| 术语 | 说明 |
| --- | --- |
| 事件 | 居民上报的一条城市问题记录，是业务主实体 |
| 工单 | 由事件派生的处理任务，一个事件在任一时点只有一个有效工单 |
| AI 建议 | 大模型输出，仅供展示与审核参考，不直接决定审核结果 |
| 全局事务 | Seata AT 管理的跨服务事务，仅覆盖数据库写操作 |
| GCJ-02 | 国测局坐标系，微信与腾讯地图统一使用 |
